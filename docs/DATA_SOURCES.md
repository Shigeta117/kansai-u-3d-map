## 2. インフラ・道路・歩道ネットワークのクリーンアップルール

`scripts/build-campus-data.mjs` では OpenStreetMap 生データのままでは不自然になる立体構造を以下のように補正しています。

1. **西門・新アクセス路（屋外エスカレーター上屋）**:
   - OSM 上の屋根付き歩行路ポリゴン（way `624590002`, `1100978545`, `1493876596`, `building=roof` 等）を建物のソリッド押出し対象から除外。
   - 代わりに `structures.json` の `accessCanopies` として抽出し、`AccessWayBuilder` が坂道に沿ったガラス上屋・支柱・エスカレーターレーン・並木桜を生成。
   - **エスカレーターは 2 台、朝のラッシュ時は 2 台とも上りになる**。時間帯は大学のバリアフリーマップの冊子（2019〜2021 年の資料。`docs/visual-research/barrier-free-map.md` 4 節）で「授業日（土曜を含む）の 8:00〜11:00 が全機上り、11:00〜18:30 が通常運転」。今もこの運用が続いていることと台数は持ち主の確認（2026-11-20）。画面には出典・年・確認日を出さず短くする（持ち主の決め 2026-11-20）。新アクセス路は階段を避けられない（同）。OSM ではこの 2 台が 1 本の way（`923172458`、`conveying=yes`）で、エスカレーターの向きの情報は無い。探索は今までどおり両向きに通れる扱いで、`walk-graph.json` ではこの way の辺だけ `rushHourUpOnly: true` を持つ。経路が下りでこの辺を通るとき（向きは辺の両端の高さの差。`RouteResult.escalatorUses`）、ルート案内のエスカレーターのチップを「エスカレーター 朝は上りのみ」にし、押すと「授業日 8:00〜11:00 は 2 台とも上り。下りは階段です。」の 1 行を出す（既定は畳む）。時刻で経路は変えない（`docs/indoor-plan.md` 8 節）。南門側のエスカレーター（way `753667566`・`753667568`）の朝の運用は未確認なので注意は出さない。
2. **秀麗橋（第3学舎〜新関西大学会館〜法文坂方面の高架歩道デッキ）**:
   - `bridge=yes` / `layer>=1` の歩道区間（way `423060539`, `423060540`, `423060541`）および未結合端点（2〜3mギャップ）を自動スナップし、地表標高に落とさず橋上 deck 標高（`yM`）を保持したまま `walk-graph.json` と `BridgeBuilder` に反映。
   - 秀麗橋を北へ渡った先（正門の北、新関西大学会館 北棟の南の端との間）の通路: 上に建物は無いが、通路の下に保健管理センターなどの施設が入っている（持ち主の確認 2026-11-24。持ち主の写真 IMG_3346 は正門の内側から北東を見たもので、橋の北の端の下に石張りの壁とガラスの入口が写る）。KAN-CAN! の部屋の一覧では保健管理センターは北棟の 4F（館内のデータ `apps/guide/src/data/indoor/senriyama-indoor.ts`）。通路の下の部分が北棟の一部か、その階が 4F に当たるかは確かめていないので、北棟の説明と地図の形（橋・北棟の輪郭）は変えていない
3. **名神高速道路（高架・地上の区間・千里山トンネルの坑口）**:
   - `highway=motorway` は地表道路リボンにせず、`structures.json` の `expressways`（上下線の車道）・`expresswayPiers`・`tunnelPortals` として `ExpresswayBuilder` が描く。仕様は `packages/core/src/data/campuses/senriyama/expressway.ts`、生成は `scripts/lib/expressway-data.mjs`。
   - 線の位置は OSM の way（高架 `425625711`・`425625712`、地上 `425625709`・`425625710`、東坑口から東 `27555334`・`374333007`、高架より西 `27555336`・`152794467`）。トンネル（`27555333`・`27555339`）は描かず、坑口をトンネルの端の中点に、トンネルの方向に直角に置く。トンネルの名前「千里山トンネル」は持ち主の確認による（2026-11-20）。
   - **高さは OSM に無いので推定**: 路面の標高は DEM（地上の区間の中央値をならし、高架の区間は両端を直線でつなぐ）から作り、上下線を同じ高さにそろえ、高架が線路・道路と交わる所で桁の下に 5.5m 以上を確保する（足りなければ路面をなめらかに持ち上げる。現状で最大 0.5m）。寸法（車道の幅 11m・床版＋桁 2.0m・高欄 1.1m・橋脚の間隔 約 30m・坑門の高さ 8.5m など）はすべて推定。橋脚は線路・ホーム・道路・建物の上を避けて置く。
   - 表示では、地上の区間の路面の下にかかる地形の格子を路面より 0.3m 下まで下げる（`carveTerrainForExpressways`。データの `terrain.json` は変えない）。
4. **阪急 関大前駅**:
   - ホーム（`railway=platform` way `467581838`・`467581839`）と駅舎（`building=train_station` way `529826319`・`668430803`・`668430804`）を `transport.json` の `stationFacilities` に出し、`StationBuilder` が描く（駅舎は周辺の建物から外す）。仕様は `packages/core/src/data/campuses/senriyama/station.ts`。
   - 上屋は国土地理院の空中写真（seamlessphoto, z18）で屋根が見える 1 番線の南端（駅舎 `668430804` の横）だけ。屋根の色は空中写真から読んだ色。駅舎の高さ（平屋 4〜4.5m）・上屋の高さ（ホームから 3m）は推定。
5. **車道の短い橋**: `bridge=yes` で長さ 15m 未満の車道（暗渠の上など）は地面に沿った帯で描く（帯が途切れないように）。
   - **以文館の連絡通路**（way `490801252`、`highway=footway`・`tunnel=yes`・`layer=-1`）: トンネルなので道の帯は描かない。両側の道（`path_423060577`・`path_490801256`）は通路の口で終わり、`walk-graph.json` では両端が 23.9m の辺でつながる。通路の形（アーチの天井・腰壁・床の坂）は以文館の専用モデル（`scene/heroes/ibunkan.ts`）が描く。幅・高さなどの寸法は持ち主の 2023 年の映像から読んだ推定
   - **凜風館の裏の大階段**（way `1259556097`、`highway=steps`）: 道の帯は描かず、KUシンフォニーホールの専用モデル（`scene/heroes/symphonyHall.ts`）が段・踊り場・花壇の箱・手すり壁で描く（`HERO_MODELED_PATH_IDS`）。凜風館の側の縁は凜風館の輪郭の北東の辺。上端は凜風館の 3 階の屋根のデッキ（凜風館の 1 階の床から 12.4m。持ち主の確認 2026-11-20「大階段の上のデッキは 4 階部分（3 階上）」）で、道からの高さを 1 段 0.155m 以下の段に割る（実際の地形で約 71 段）。段の割り付け（道から全幅の 8 段、5 回の上りと 1.6m の踊り場、上に 4m の踊り場）と 2・3 階の階高 4.1m は持ち主の 2023 年の映像から読んだ推定。`walk-graph.json` は今までどおり
   - **凜風館のデッキから屋上の庭へ上る階段**（way `423060533`、`highway=steps`）: 道の帯は描かず（地面の高さの帯は建物の中に入る）、凜風館の専用モデル（`scene/heroes/rimpukan.ts`）が南東の辺に沿って 3 階の屋根から屋上の庭まで段を描く（`HERO_MODELED_PATH_IDS`。幅・段の寸法・上端の位置は空中写真と映像 IMG_6416 から読んだ推定）。`walk-graph.json` は今までどおり
   - **第3学舎連絡デッキの屋根と壁**（way `423060539` の全長。南棟のデッキとの合流点から道路 `path_158856536` の上をまたいで第3学舎の側の端まで）: `BridgeBuilder` の `DECK_ROOF_SECTIONS` で、高いコンクリートの壁と網状の金属のアーチの屋根を足す。地上へ下りる階段（way `490793066`）の合流点で屋根が途切れて南の壁が開き、第3学舎へ入る短い橋（way `490793070`）の口では南の壁だけが開く（持ち主の 2023 年の映像 IMG_6436・6437）。壁と屋根の高さ、途切れる長さ、デッキの幅 4.6m（壁の内側 約 4.1m。映像の床の幅とカメラの高さの比から）はすべて推定
6. **グラウンド（陸上のトラック・直線の走路・観客席・野球場・テニスコート）**:
   - 位置と輪郭は OSM（トラックの外周 relation `11114488` の outer way `491574942`、人工芝 `805366949`、直線の走路 `805817744`、観客席 `805366951`（`building=yes, layer=1`。建物の箱にせず座席の面として描く）、野球場 `423067262`、テニスコート `497645766`・`497645758`、第4学舎3号館の屋上のコートは建物 `423067232` の輪郭を 1.2m 縮めた範囲）。作り方は `packages/core/src/data/campuses/senriyama/grounds.ts`、生成は `scripts/lib/grounds-data.mjs`、描くのは `GroundsBuilder`（`structures.json` の `grounds`）
   - 線・レーン・コートの模様は 1 枚のテクスチャ（canvas）に描いて面に貼る。面・網の柵・外野のフェンスの 3 つのメッシュ
   - **推定**: トラックは標準の 400m（直線 84.39m・内側の半径 36.5m）の 8 レーン（空中写真の西の直線の白線の数から）をフィールドの向きに合わせた。サッカーの線は標準の 105×68m。直線の走路は 4 レーン。観客席の前の縁はトラックの面から 1.0m、後ろの縁は後ろの地面の最も高い所から 0.6m。野球場の本塁と両翼のポールの位置は空中写真のファウルラインから（本塁は北東の角、両翼 約 92m）、内野の土は投手板を中心に半径 28m、フェンスの手前の土の帯 4.5m、外野のフェンスの高さ 3m。テニスコートの面の数（3・3・屋上 4）は空中写真から、網の柵の高さ 4m。面の色は空中写真の色（テニスコートは 2017 年の写真の色）
   - 観客席の OSM の輪郭は第4学舎3号館（way `423067232`）の東の角の下に入っているので、3号館の輪郭を 5m 外へ広げた範囲を引く（`grounds.ts` の `keepClearOf`、`subtractConvex`）。5m は空中写真（3号館の南東の辺の外に暗い帯と明るい通路があり、座席の列は辺から 5.5〜6.5m で始まる）から読んだ推定
   - 地面のグラウンドの面の高さは、輪郭の中の地形の中央値（直線の走路は中央グラウンドと同じ高さ）。表示ではグラウンドにかかる地形の格子をその高さにならし（`carveTerrainForGrounds`。データの `terrain.json` は変えない）、観客席の下は座席の面より上に出る地形だけを下げる
   - 第4学舎3号館の屋上は空中写真・公式の地図でテニスコートなので、屋上の塔屋の箱（`area4-white-lab` の造形）を置かない
   - 作らなかった物: 一高のグラウンド（OSM の way `484112544`。ジオラマの範囲の南の外）、千里山北広場（地形の標高データが造成前の丘のままで 16m の高低差があり、平らな人工芝の面を置く高さが分からない。塗り分けの色だけ人工芝の緑に）
7. **3モード歩行グラフ（最短 / 坂ひかえめ / 完全段差フリー）**:
   - `step-free` モード時は `isSteps` および `isEscalator` エッジコストを `Infinity` とし、`accessibleWalkNodeId`（階段・エスカレーターを含まない主連結成分 2,125ノード）を用いて探索。

## 3. 座標系とジオラマ投影設計

- **投影原点（千里山キャンパス）**: `34.7745°N, 135.5105°E`
- **右手系 Y-up ローカル座標（単位: m）**:
  - `+X` = 東方向（`Δlon × 111320 × cos(originLat)`）
  - `-Z` = 北方向、`+Z` = 南方向（`-Δlat × 110940`）
  - `+Y` = 標高方向（地形メッシュ・ルート表示は垂直強調率 `1.35` を適用）
- **ジオラマ範囲**: `x ∈ [-540, 580]`（東西 `1,120m`）、`z ∈ [-480, 580]`（南北 `1,060m`）
- **実測チェックポイント標高（GSI DEM5A）**:
  - 阪急 関大前駅: `25.64m`
  - 関西大学 正門: `37.08m`
  - 悠久の庭: `41.34m`
  - 第1学舎1号館（高台）: `53.24m`

## 4. オープンソースにおけるライセンス分離方針

1. **MIT License（コード・独自造形）**:
   - `packages/`、`apps/` 以下のアプリケーション・3Dエンジン・探索ロジックおよび `scripts/` 以下の生成ツールは MIT License とします。
2. **生データキャッシュの分離（`.cache/`）**:
   - `scripts/fetch-open-data.mjs` が取得する生の OSM JSON や DEM PNG タイルは `.cache/raw/` に保存され、`.gitignore` により Git 管理外としています。
3. **JSON データ（`public/data/` — Derivative Database / ODbL v1.0）**:
   - `public/data/` の JSON は OpenStreetMap から抜き出して加工した **Derivative Database** として **Open Database License (ODbL) v1.0** で提供します（`© OpenStreetMap contributors`）。標高データ（`terrain.json` と各データの標高値）は「出典：国土地理院 地理院タイル（標高タイル）を加工して作成」が適用されます。詳細は [`public/data/senriyama/LICENSE.md`](../public/data/senriyama/LICENSE.md) を参照してください。
4. **3Dモデル出力（`exports/` — Produced Work）**:
   - `npm run export:3d` が書き出す `.glb`/`.obj`（Git 管理外）は ODbL の **Produced Work** として、出典表記および `THIRD_PARTY_NOTICES.md` を付けて配布します。
5. **館内のデータ（`apps/guide/src/data/indoor/` — `public/data/` とは別）**:
   - 大学が公開している資料（KAN-CAN! の部屋の一覧・バリアフリーマップ）から事実だけを自前の形にした物で、OSM の Derivative Database（ODbL）には入れない。出典と版はデータの中（`IndoorSource`、`BuildingFloorPlan.sourceName` など）に持つ（`docs/indoor-plan.md` 3 節）
   - バリアフリーマップの事実は `apps/guide/src/data/indoor/barrier-free/`。資料の画像・文章・図の上の位置（px）は入れていない
   - 第1学舎の入口・連絡路の口の平面の点（`apps/guide/src/data/indoor/l1/area1.ts`）は、バリアフリーマップの図を OSM の輪郭の角に合わせて移した推定で、点は OSM の輪郭の上に置いた

### 誠之館の建て替えの封鎖範囲（確認 2026-11-24）

出典は持ち主の現地確認（2026-11-24。アプリの画面に封鎖の範囲を手描きした物と、通れる所・通れない所の説明）と、同じ日の持ち主の写真。大学の資料に範囲の図は無い。

- **データ**: `public/data/senriyama/closures.json`。範囲の多角形（`area`）・囲いの線（`fences`）・範囲にかかる建物の扱い（`buildings`）・通路の扱いと入口の付け替え（`walk`）を 1 か所に持ち、確認日（`asOf`）と出典（`sources`）を付ける。工事の進み具合で範囲は変わるので、変わったらこのファイルだけを直す（経路の `walk-graph.json` は作り直さない）
- **起こし方**: 手描きの画面とアプリの描画を重ねてカメラを当てはめ（地面の模様の残差 0.43px ≒ 5cm）、手描きの線の画素を地形のメッシュに当てて座標にした。誤差の大半は手描きそのもの（線の太さ約 0.9m、位置のぶれ 1〜2m）。手描きは 3 本の線で、端は建物の壁に着いている。有鄰館・3号館（旧館）・2号館の壁でつないで 1 つの範囲にした（約 6,500m²）
